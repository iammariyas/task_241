1. **Raid массивы, что такое и какие бывают**
	RAID (Redundant Array of Independent Disks - избыточный массив независимых дисков) представляет собой технологию объединения нескольких накопителей в один логический диск для увеличения производительности и/или надёжности системы при отказе отдельных элементов массива.
	
	Если говорить проще, то RAID-массив - это несколько дисков соединенные в один диск с выделением места под хранение информации для исправления ошибок в данных.
	
	**RAID-массивы классифицируются по следующим параметрам:**
	- по исполнению RAID-контроллера
	- по типам поддерживаемых интерфейсов накопителей
	- по поддерживаемым уровням RAID
	
	я нашла картинку с краткой выжимкой уровней в таблице:
	
	![alt text](https://github.com/iammariyas/task_241/blob/labs/Homework_Kruleva_Maria/image/Pasted%20image%2020251229232834.png)
	Однако в табличке нет уровней JBOD, RAID DP и RAID 7. Про них я расскажу подробнее:
	**JBOD** - это не RAID, но тоже массив, его аббревиатура расшифровывается как "просто связка дисков". Она не дает никакого роста производительности и никакой отказоустойчивости, является просто дисками, которых склеили в один диск. скорость операций не выйдет за рамки самого быстрого и самого медленного накопителя, участвующих в этой связке
	**RAID DP** - это усовершенствованный уровень RAID. он получился после того, как в RAID4 добавили еще один накопитель для хранения контрольных сумм. Однако в этом RAID DP используется ФС WALF из-за чего он может работать только в устройствах компании *NetApp*. Но связка RAID DP с этой системой дает повышение производительности выше, чем у RAID 5 и RAID 6.
	**RAID 7** - это запатентованная технология, разработанная компанией *Storage Computer Corporation*. По сути, это модифицированный RAID 4, в который добавлено асинхронное кэширование операций чтения и записи с использованием оперативной памяти (ОЗУ). 
	
	Для устойчивой работы такого массива **обязательно требуется источник бесперебойного питания (ИБП)**, поскольку при внезапном отключении электричества данные, находящиеся в кэше, могут быть потеряны или повреждены.

	Проверим состояние массива через `cat /proc/mdstat`

5. **Удалите raid0 и создайте raid1**
	Чтобы удалить RAID 0 использую команду, нужно остановить рейд массив с помощью команды `mdadm --stop /dev/md0`, а потом очистить суперблоки на дисках `mdadm --zero-superblock /dev/sdc /dev/sdd`/ проверяем, что диски очищены `mdadm --examine /dev/sdc /dev/sdd`. Должно быть пусто или "No md superblock detected".
	![alt text](https://github.com/iammariyas/task_241/blob/labs/Homework_Kruleva_Maria/image/Pasted%20image%2020251230001739.png)
	Далее создаем RAID 1
	```
	mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdc /dev/sdd
	```
	проверяем, что создали `cat /proc/mdstat`
	вывод такой: 
	```
	md0 : active raid1 sdd[1] sdc[0]
	```
6. **В чём между ними разница?**
	RAID 0  обеспечивает максимальную производительность за счет распределения данных по дискам, но не имеет отказоустойчивости - сбой одного диска приводит к полной потере данных. в отличие от него, RAID 1 использует половину дискового пространства для создания полной копии данных на втором диске, гарантируя высокую надежность и доступность даже при отказе одного накопителя.
7. **Есть ли файловые системы которые поддерживают raid массивы без стороненго ПО**
	файловые системы, такие как ZFS, GPFS, Btrfs и XFS, предоставляют встроенную поддержку RAID.
	
8. **Можно ли создать raid массив во время установки системы?**
	Можно. Современные установщики Линукса и даже Альт линукса, предоставляют инструменты для создания software RAID прямо в процессе разметки дисков. Можно выбрать разделы на физических дисках, указать для них тип Linux RAID и затем собрать из них массив нужного уровня.
